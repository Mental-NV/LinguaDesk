### 5.3 DeepSeek documentation checked on 2026-09-11

The direct DeepSeek API is the selected **initial evaluation candidate**, not a chosen production provider or qualified fallback. The owner-supplied profile and current official documentation agree on display name `DeepSeek-V4.1-Flash`, requested model `deepseek-flash` and OpenAI-format base URL `https://api.deepseek.com`. DeepSeek documents that legacy `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` requests are now served by V4.1 Flash at the Flash price. A mutable alias is not an immutable model snapshot; record the requested ID and returned model/fingerprint when available. [DeepSeek quick start](https://api-docs.deepseek.com/)

DeepSeek's quick start authenticates its OpenAI-compatible endpoint with an API key. The environment credential source, shared evaluation/serving scope, credential-reference naming, redaction and provider-neutral access-check workflow are project decisions owned by [LLM specification Section 5.2](../04-llm-specification.md#52-evaluation-profiles-and-credentials); this provider snapshot does not make the secret part of a candidate profile or select DeepSeek-only tooling.

For Chat Completions, explicitly send `thinking: {"type":"disabled"}`; thinking is enabled by default. An “OpenAI-compatible” client or a low reasoning-effort setting is not evidence that this field reached the provider. Verify the serialized request in adapter tests. [DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)

DeepSeek documents `response_format: {"type":"json_object"}` and asks for a JSON instruction and example. Empty content can still occur. Use this format and local envelope checks; do not assume JSON Schema enforcement from compatibility branding. [DeepSeek JSON output](https://api-docs.deepseek.com/guides/json_mode/)

The published V4.1 Flash tariff checked on 2026-09-11 is USD per million tokens:

| Token category | Off-peak | Peak |
| --- | ---: | ---: |
| Input cache hit | 0.003 | 0.006 |
| Input cache miss | 0.15 | 0.30 |
| Output | 0.60 | 1.20 |

The same page lists a 1M-token context and a 384K-token maximum output. Peak hours are 01:00–04:00 and 06:00–10:00 UTC, Monday through Friday; all other hours use the documented half-price off-peak rates. These are provider ceilings and public list prices, not application defaults, permission to accept longer source text or evidence of the account's effective billing. Use peak cache-miss/output rates for conservative reservations unless the actual billing contract establishes a tighter bound; recheck the tariff before paid use. These documentary numbers do not set the project cap or establish total request cost. [DeepSeek models and pricing](https://api-docs.deepseek.com/quick_start/pricing/)

Provider-managed context caching reuses eligible input prefixes; output is still generated and cache hits are best effort. Record the provider's hit/miss token evidence, and keep stable prompt prefixes without including unrelated text or padding solely to seek a cache hit. Cache-hit latency/cost must be measured separately from cache misses. [DeepSeek context caching](https://api-docs.deepseek.com/guides/kv_cache/)

Adapter conformance must preserve documented completion status and usage information, including cache and reasoning breakdown where returned. Missing usage is unknown, not zero. Request caps must be explicitly sent rather than relying on the large provider limits. [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
