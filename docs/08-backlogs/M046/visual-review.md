# M046 visual review

2026-10-26 (Europe/Moscow), Codex visual review under D-22. Inspected each new baseline at native resolution after the explicit update run: RTL Translator and RTL Write at viewport sizes 1440×900 and 390×844, plus `artifacts/m046/script-glyphs.png`. Captures are full-page PNGs, so document heights can exceed viewport height to include the lifetime footer. Existing M045 snapshot bytes did not change.

## Findings

- Arabic Translator: connected glyphs, right-aligned generated content and punctuation are readable; English controls/navigation remain LTR. Desktop editors remain equal, and narrow layouts stack without horizontal overflow. English→Arabic→English swap uses the real API and updates both selectors once. Native editing/copy checks preserve exact logical Arabic, newlines, URL and time strings after the capture.
- Hebrew Write: the generated sentence and both option buttons render RTL. The English deletion label remains LTR while the deleted Hebrew phrase is isolated and struck through. Changes, sentence focus, editing/copy actions and alternatives remain visible at both widths. Native option selection changes only the selected occurrence, and cache/copy actions do not charge again.
- Script sheet: inspected Arabic/Hebrew, Devanagari consonant+virama+joiner and combining-accent text, Ethiopic, Myanmar, Khmer, Thai, Japanese and Korean. No missing-glyph boxes, clipped marks or broken line spacing were visible. Mixed paragraphs retain local direction. The test also verifies exact native textarea values and clipboard strings.
- Long constrained-script names and the three-letter selection are covered by native control assertions; the 320 px journey verifies document reflow without overflow. Hindi/Japanese/Korean/Filipino result, alternatives, editing and copying use real auth/API/migrated SQLite with controlled external adapters. A new-language case also signs in through the real login form.

Font identities and byte hashes are pinned in `frontend/tests/e2e/fonts/manifest.json` and `manifest.m046.json`. The latter contains test-only Noto Sans Arabic, Hebrew, Devanagari, Ethiopic, Myanmar, Khmer, Thai, Lao, JP and KR 400-weight subsets, retrieved from recorded Google Fonts URLs under the included SIL OFL. FontTools 4.60.1 checked the combined cmap against the selected visual sample; `artifacts/m046/font-coverage.json` records zero missing sample code points. All screenshot fonts are injected from pinned local bytes; product text paths fetch no font or other remote resource.

The first expanded capture run exposed a test attempting to select a disabled same-language target before changing its source. The native selector correctly blocked it; the test now changes source first. Failed run logs are retained under `artifacts/m046/`; no product bypass was added. A normal smoke run must compare all baselines after this inspection. Physical devices, native IMEs, assistive technology and additional browser engines remain untested optional evidence. These deterministic captures do not establish model language quality.
