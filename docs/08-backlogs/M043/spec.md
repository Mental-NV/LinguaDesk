# M043 — Selected specification
Selected items: BI-043. Status: ready; completion evidence in tasks.md.
Sources: [context manifest](context.json); [backlog](backlog.md).

## Scope

M043 wires the existing operation path to live serving. New `Infrastructure/Serving/` providers (`ServingTranslationClientProvider`, `ServingRewritingClientProvider`) implement the existing `ITranslationClientProvider` / `IRewritingClientProvider` interfaces over `ChatCompletionsAdapter` + `CandidateRegistry` as primary-only serving chains (no fallback per DF-004). A validated `Serving` config section carries per-family `CandidateId`, `CredentialRef` and `MaxSpendUsdPerOperation: 0.05`; the secret reuses the owner-exported `LINGUADESK_AIEVALUATION__CREDENTIALS__DEEPSEEK__APIKEY` (blank/absent = unconfigured). Registration in `OperationsRegistrationExtensions` selects serving providers only when the section validates; otherwise the `Unavailable*` providers stay as the fail-closed fallback. `scripts/backend.sh run` validates serving config at startup and exits non-zero naming the missing variables when unconfigured. Per-dispatch admission stays with `MonetaryAdmissionService`; both coordinators honor the $0.05 per-operation ceiling instead of passing `budget: null`. UX keeps 202-pending semantics for genuinely pending operations; an unconfigured service never presents a retry loop because startup fail-fast is the primary guard.

Explicit exclusions: candidate qualification (G1) and full-corpus coverage (M035/M036 own quality); rate limiting beyond the per-operation cap; CI integration of the live suites; route-specific providers and multi-candidate fallback chains (DF-004); mail/verification (DF-008); automatic pause submission (DF-003); prefix charging (DF-006); any new provider key provisioning (the `..._MUSE__APIKEY` variable is not consumed; serving candidate is DeepSeek only); any UI redesign or new message copy (existing MSG IDs only).

## Constraints and decisions

Owner-locked by the roadmap change note and the owning proposal: serving candidate `DeepSeek-V4.1-Flash`, env-only purpose-scoped credentials, $0.05 per-operation ceiling in config with environment overrides, fail-fast `run`. Per LLM §5.1 the serving snapshot is primary-only; repeating a candidate as fallback is rejected as a hidden retry. Per LLM §7, a provider access/balance failure on the shared `deepseek` credential scope blocks that scope for the operation (no second candidate through the same blocked scope); exhaustion surfaces the processing category with zero charge. Per API §8, provider errors never leak to clients; budget failures use the budget category, never a language-validation failure. Q-001 stays open: M043 consumes only the serving slice (candidate identity, tariff bounds, credential); quality/performance/production qualification remain with M036+/M037 and release gates. Human gates: live-suite evidence (AC-005/AC-006) requires the owner-authorized opt-in run at the end; all other ACs are proven by automation with fake/scripted adapters.
