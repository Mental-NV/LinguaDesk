## 1. Outcome and authoritative inputs

An independent API consumer can submit a local email/password registration without loading the SPA. Valid new details create exactly one durable, unverified ASP.NET Core Identity account and request one deterministic confirmation delivery; malformed or policy-invalid details are rejected without an account. The response never authenticates the caller, returns a credential/token/account identifier, invokes language work or implies that email verification/live delivery is complete. Repeated or concurrent use of an already registered normalized email is externally indistinguishable from an accepted registration and creates neither a second account nor a second registration delivery.

### BI-006 — Register one durable unverified local account

**API/account value:** Add only `POST /api/accounts/register`. A valid request contains required `email` and `password`; confirmation belongs in the web form, not the API payload. A new normalized email produces one unverified Identity account and one call to the narrow confirmation-delivery boundary. Success is a generic no-store `202` verification-required acknowledgment. A syntactically valid duplicate or concurrent loser produces the same observable acknowledgment, no new account and no new delivery, so callers cannot enumerate membership from status or body. Validation failures use the selected RFC 9457 field-error contract and create no account.

**Credential and verification value:** The selected local password policy is 15–128 well-formed Unicode scalar values, with spaces allowed, no trim/normalization/truncation and no uppercase/lowercase/digit/symbol composition rule. Email is required, has no surrounding whitespace, uses .NET `EmailAddressAttribute`, has a 254-scalar maximum and is unique through Identity's invariant uppercase normalized lookup. Registration issues no cookie, bearer/refresh credential, confirmation code or account identifier. The persisted account starts with `EmailConfirmed = false`; the named verified-account authorization policy checks current durable status and denies it. No language route/provider exists in this slice.

**Indispensable operational value:** Extend the checked-in EF migration chain with the standard Identity schema without rewriting M003's applied migration. Configure a fixed application name and explicit durable Data Protection key directory. Before database-dependent account serving listens, validate that the configured database exists, is current/openable/writable and that the existing key directory is usable; expose storage/key readiness separately from unchanged process liveness. OpenAPI generation remains side-effect-free and uses no database, key write or email adapter.

**Exclusions:** No sign-in/out, cookie or bearer/refresh issuance, antiforgery bootstrap, confirmation completion, resend/cooldown, account-status read, password reset, frontend form adoption, real email provider, live delivery/click, account deletion, roles/admin behavior, LLM endpoint/admission, allowance/accounting, Google/OAuth, short-term abuse rate, password breach-list claim or API compatibility promise. M007 owns confirmation/resend behavior and deterministic link completion; M008/M009 own cookie/bearer access; M011 owns the web form; M034 owns live email evidence. Q-004 deletion/backup lifecycle and P-005/P-006 remain at their current authorities.

**Edge and nonfunctional checks:** Reject missing/extra/duplicate JSON fields, malformed JSON/content type, invalid email, malformed Unicode password and 14/129-scalar passwords without echoing credentials or logging bodies. Accept exactly 15/128 scalars and space-containing passphrases. Case variants of one normalized email and simultaneous requests create one row/delivery. Delivery failure leaves the new account unverified and retains the same generic acknowledgment; later resend is the recovery path. Persistence survives restart, generated schema/types contain only implemented paths, unknown API/health/static routes retain their boundaries, and test fakes cannot be selected by production configuration.
